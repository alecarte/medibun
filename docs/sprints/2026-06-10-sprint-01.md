# Sprint 01 — 2026-06-10 → 2026-06-24

Capacity: full-time (~60–80h). Focus: **BFF skeleton + CI**, with the Aureva data model designed
alongside as a docs/review task. BFF runtime is **not pre-decided** — ADR first, decision
checkpoint with Alec before scaffolding.

## Context

Phase 0 (bootstrap steps 1–5) is complete and merged (PR #1, d557d75). The architecture routes
every product surface through a backend (BFF) that doesn't exist yet — `@medibun/api-client` is a
stub with nothing to call. The definition of done (typecheck/lint/test) has no CI enforcing it.
`DATA_MODEL.md` is an ask-first placeholder. This sprint turns the foundation into running
software without touching production, real PHI, or auth implementation.

## Goals (each with its verify step)

1. **CI pipeline** — GitHub Actions running `typecheck` / `lint` / `test` / `build` via Turbo on
   PRs and `main`, with pnpm + Turbo caching. Plus PR template reflecting the definition of done,
   and branch protection on `main`.
   _Verify:_ a PR with a deliberately failing test goes red; main goes green.
2. **ADR-0001 BFF runtime + ADR-0002 experience DB** — short ADRs in `docs/adr/` comparing options
   (runtime: Hono vs Next route handlers vs Fastify; DB: managed Postgres flavor + ORM), under the
   constraints: only Medplum SDK holder, HIPAA-eligible hosting (Vercel Pro+HIPAA approved in
   principle), thick-BFF responsibilities.
   _Verify:_ **decision checkpoint with Alec** — both ADRs accepted before goal 3 starts.
3. **`apps/api` BFF skeleton** on the chosen runtime — health endpoint, env/config handling,
   PHI-safe error handling and request logging (resource/correlation IDs only, never PHI values),
   `@medibun/medplum-backend` wired in as the only Medplum session holder.
   _Verify:_ unit tests for middleware/config; runs locally against the docker-compose Medplum.
4. **Vertical slice (dev-only, synthetic data)** — patient profile end to end: local Medplum →
   BFF domain DTO → typed `@medibun/api-client` method → portal page render. No real auth — a
   dev-only guard; this proves the anti-corruption boundary with running software.
   _Verify:_ tests at each layer (DTO translation unit test, api-client contract test, portal
   render test); manual run shows a synthetic patient's profile in the portal.
5. **Aureva FHIR data model v1 draft** in `docs/DATA_MODEL.md` — booking/scheduling, treatment
   series + injection maps, consents, memberships, with the FHIR-vs-experience-DB split and
   AccessPolicy/audit implications per resource. **Design for review, not implementation** — this
   draft _is_ the "ask before modeling" artifact.
   _Verify:_ review checkpoint with Alec; open questions listed explicitly.
6. **Auth design doc** (`docs/adr/` or `docs/AUTH.md`) — patient + staff identity, session flow
   through the BFF, Medplum profile linkage. Design only; auth implementation is approval-gated
   and out of scope.
   _Verify:_ doc exists with a recommended approach and its approval-gated items flagged.

**Stretch:** Renovate (lockstep `@medplum/*` group), design-token expansion (spacing/type scale),
Vercel preview deploy of `apps/api`.
